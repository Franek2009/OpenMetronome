# Weryfikacja kandydata 0.13.0-beta.3

Stan 2026-10-31: kod na branchu `fix/backup-crash-recovery`, versionCode 15.
Kandydat nie jest opublikowany. Publicznym wydaniem pozostaje beta.2.

## Zmiany i granice

Trwały dziennik przechowuje pełne migawki przed i po przywróceniu. Gotowość
magazynów oraz Start czekają na odzyskanie. Brak znacznika zatwierdzenia
wybiera poprzedni zestaw; zatwierdzony dziennik wybiera nowy zestaw.
Uszkodzony dziennik blokuje operacje i zachowuje materiały. Szczegóły:
[protokół odzyskiwania](RESTORE-RECOVERY.md).
Format `.ombak` v1 i schemat Room 2 bez zmian.

- Lint debug/release: zero błędów, po pięć ostrzeżeń o nowszych narzędziach

użytkownika. `allowAudio=false`, `allowHaptics=false`.

## Aktualizacja z beta.2

API 26 i API 35: **PASS**. Publiczny, podpisany APK beta.2 sprawdzono pod kątem
wersji i odcisku oficjalnego certyfikatu. Kopie beta.2 i kandydata podpisano
jednorazowym kluczem testowym; nie używano klucza oficjalnego. Po imporcie
syntetycznej kopii przez rzeczywisty DocumentsUI wykonano `adb install -r`,
eksport z nowej wersji i porównanie ustawień, presetów, pełnej historii,
podsumowań dni, metadanych sampli i dokładnych bajtów plików. Dane zachowane.
Nie jest to test aktualizacji między dwoma oficjalnie podpisanymi wydaniami.

API 35: pierwsza próba skryptu zatrzymała się przy przejściowo pustym korzeniu
accessibility. Po poprawie oczekiwania oraz usuwaniu starego dumpu przed odczytem
powtórzono cały przebieg na świeżym własnym AVD; PASS. Pierwszej próby nie zaliczono.
Logi lokalne: `app/build/reports/upgrade-validation/api26/` oraz `api35/`.
Nie odinstalowywano ani nie czyszczono aplikacji użytkownika.

## Regresja UI i pełne zestawy

Pierwszy pełny API 26: **55 PASS, 6 AUDIO_SKIPPED, 0 OTHER_SKIPPED, 3 FAIL**,
64 przypadki. Błędy dotyczyły sterowania pickerem i synchronizacji klawiatury
w testach treningu/presetów. Nie jest to zaliczenie pełnej regresji.
Pierwsza powtórka trzech przypadków również nie przeszła; następna zaliczyła
trening i presety, a diagnostyka wykazała brak ACTION_CLICK dla wiersza pliku
w DocumentsUI Oreo. Poprawiono oczekiwanie na zamknięcie IME i wybór rzeczywistej
pozycji listy; dodano dotknięcie rozpoznanego wiersza, gdy brak akcji dostępności.
Pierwszy pełny API 35: **56 PASS, 6 AUDIO_SKIPPED, 0 OTHER_SKIPPED, 2 FAIL**.
Po poprawkach trzy scenariusze UI przeszły wspólnie dwukrotnie na API 35.
Dalsze próby API 26 ujawniły powrót z pickera przed gotowością Compose,
nieskuteczne ACTION_CLICK na kontenerze listy oraz niestabilną zmianę nazwy.
Dodano oczekiwanie na dialog, rzeczywisty dotyk wiersza, bezczynność systemowego
okna i stabilne położenie przycisków. Starszy Android wykrywa zamknięcie IME
względem pełnego ekranu, a nie zmniejszanego okna aplikacji.

Jedna próba diagnostyczna z zewnętrznym `uiautomator dump` podczas instrumentacji
spowodowała konflikt rejestracji UiAutomation w emulatorze API 26. Nie zaliczono
jej; emulator zrestartowano bez kasowania danych. Podczas kolejnych przebiegów
nie uruchamiano równoległego klienta UiAutomation.
Kolejny pełny API 35: **57 PASS, 6 AUDIO_SKIPPED, 0 OTHER_SKIPPED, 1 FAIL**
(picker). Kolejny pełny API 26: **56 PASS, 6 AUDIO_SKIPPED, 0 OTHER_SKIPPED,
2 FAIL** (widoczność przycisku i zmiana nazwy presetu). Żadnego nie zaliczono.
Picker API 35 poprawiono przez aktywowanie karty pliku z wykluczeniem kontenera
listy. Diagnostyka presetów potwierdziła ponowne otwarcie IME przez nadal
sfokusowane pole Compose. Próba przeniesienia fokusu na przycisk w trybie
dotykowym nie powiodła się. Ostateczne rozwiązanie dodaje akcję „Gotowe” do
edytorów liczb treningu i nazwy presetu; akcja zwalnia fokus bez zmiany walidacji.
Ekran presetów ma neutralny cel fokusu, aby Oreo po „Gotowe” nie wracało do
jedynego edytora. Testy klikają pole, wykonują akcję IME i czekają na utratę
fokusu. Oczekiwanie na widoczny przycisk uwzględnia zmianę zakresu przewijania
po aktualizacji danych.

Dalszy picker API 26 zwrócił pusty aktywny korzeń mimo poprawnie wyrenderowanego
okna na zrzucie zapisanym przez test. Dodano pobieranie korzenia aktywnego lub
fokusowanego okna; nie aktywujemy zasłoniętych okien w tle. Po tej ostatniej
zmianie picker Samsunga zaliczono ponownie: **1 PASS**, 13,485 s.

Próby lokalnego API 35 z `swiftshader_indirect` miały także dialog ANR System UI
i błędy ColorBuffer w logu emulatora. Zestawy z takim błędem nie są PASS.
Jedna powtórka nie wystartowała instrumentacji, gdy boot przekroczył limit
oczekiwania skryptu. Po zamknięciu własnego AVD uruchomiono ten sam obraz bez
czyszczenia danych, z `-gpu software`, 2048 MB i dwoma rdzeniami. Animacje obu
emulatorów wyłączono jak w CI; ustawień Samsunga nie zmieniano.

W starszym CI test zachowania akcentów po obrocie założył, że kontrolka nadal
mieści się w bieżącym viewport. Końcowa instrumentacja przewija do kontrolki
przed sprawdzeniem jej widoczności; oczekiwane wartości pozostają bez zmian.
Ten test po końcowej zmianie zaliczono dodatkowo na obu emulatorach i Samsungu:
po **1 PASS**, zero pominięć i błędów (`rotation-final.log` w każdym katalogu).

Sześć pominięć to cztery krótkie i dwa długie testy audio. Nie są zaliczeniami.
Wszystkie zestawy używały `allowAudio=false`, `allowHaptics=false` oraz
izolowanych danych. Nie aktualizowano ani nie usuwano zwykłej aplikacji użytkownika.

Logi prób zachowano w `app/build/reports/crash-recovery/`.
