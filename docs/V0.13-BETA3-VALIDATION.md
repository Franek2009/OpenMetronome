# Weryfikacja kandydata 0.13.0-beta.3

Stan 2026-10-31: kod na branchu `fix/backup-crash-recovery`, versionCode 15.
Kandydat nie jest opublikowany. Publicznym wydaniem pozostaje beta.2.

## Zmiany i granice

Trwały dziennik przechowuje pełne migawki przed i po przywróceniu. Gotowość
magazynów oraz Start czekają na odzyskanie. Brak znacznika zatwierdzenia
wybiera poprzedni zestaw; zatwierdzony dziennik wybiera nowy zestaw.
Uszkodzony dziennik blokuje operacje i zachowuje materiały. Szczegóły:
[protokół odzyskiwania](RESTORE-RECOVERY.md).
Format `.ombak` v1 i schemat Room 2 bez zmian.

## Testy lokalne

- **136 JVM PASS**, zero błędów i pominięć. Pięć nowych scenariuszy dziennika.
- Lint debug/release: zero błędów, po pięć ostrzeżeń o nowszych narzędziach
  i zależnościach. Build debug, instrumentacji oraz unsigned release PASS.
- Analiza **172 klików PCM PASS**, bez odtwarzania.
- Parser instrumentacji: siedem scenariuszy PASS. Skrypty wydawnicze PASS,
  w tym odmowa testowania aktualizacji na urządzeniu fizycznym i odmowa użycia
  debuggable APK po obu stronach aktualizacji.
- Oracle aktualizacji: dwa testy PASS, w tym sześć wariantów uszkodzenia danych;
  asercje działają także przy `PYTHONOPTIMIZE=1`.
- Wstępny zestaw odzyskiwania API 35: **13 PASS**, 24,228 s. Obejmuje rzeczywiste
  zabicie osobnego procesu w dziewięciu granicach importu i trzech granicach
  odzyskiwania, łącznie 15 przerwań procesu na przebieg obu metod.

Testy używają syntetycznych danych w izolowanym magazynie i oddzielnego pakietu
`org.openmetronome.validation`. Debug-only usługa `:restore_probe` jest
nieeksportowana, sprawdza własną nazwę procesu i operuje tylko na UUID w cache.
Nie znajduje się w release APK. Nie zabija procesu instrumentacji ani aplikacji
użytkownika. `allowAudio=false`, `allowHaptics=false`.

## Aktualizacja z beta.2

API 26 i API 35: **PASS**. Publiczny, podpisany APK beta.2 sprawdzono pod kątem
wersji i odcisku oficjalnego certyfikatu. Kopie beta.2 i kandydata podpisano
jednorazowym kluczem testowym; nie używano klucza oficjalnego. Po imporcie
syntetycznej kopii przez rzeczywisty DocumentsUI wykonano `adb install -r`,
eksport z nowej wersji i porównanie ustawień, presetów, pełnej historii,
podsumowań dni, metadanych sampli i dokładnych bajtów plików. Dane zachowane.
Nie jest to test aktualizacji między dwoma oficjalnie podpisanymi wydaniami.

API 35: pierwsza próba skryptu zatrzymała się przy przejściowo pustym korzeniu
accessibility. Po poprawie oczekiwania oraz usuwaniu starego dumpu przed odczytem
powtórzono cały przebieg na świeżym własnym AVD; PASS. Pierwszej próby nie zaliczono.
Logi lokalne: `app/build/reports/upgrade-validation/api26/` oraz `api35/`.
Nie odinstalowywano ani nie czyszczono aplikacji użytkownika.

## Regresja UI i pełne zestawy

Pierwszy pełny API 26: **55 PASS, 6 AUDIO_SKIPPED, 0 OTHER_SKIPPED, 3 FAIL**,
64 przypadki. Błędy dotyczyły sterowania pickerem i synchronizacji klawiatury
w testach treningu/presetów. Nie jest to zaliczenie pełnej regresji.
Pierwsza powtórka trzech przypadków również nie przeszła; następna zaliczyła
trening i presety, a diagnostyka wykazała brak ACTION_CLICK dla wiersza pliku
w DocumentsUI Oreo. Poprawiono oczekiwanie na zamknięcie IME i wybór rzeczywistej
pozycji listy; dodano dotknięcie rozpoznanego wiersza, gdy brak akcji dostępności.
Wynik końcowego pełnego zestawu zostanie dopisany po zakończeniu.

Logi prób zachowano w `app/build/reports/crash-recovery/`.

## Pozostałe bramki

CI tego PR wymaga potwierdzenia. Samsung nie jest obecnie dostępny w ADB;
nie zaliczamy testów sprzętowych beta.3. Lenovo pominięte zgodnie z decyzją
użytkownika. Nie wykonywano audio, wibracji ani sesji 30-minutowej.

Zabicie procesu nie jest sprzętowym testem odcięcia zasilania ani pomiarem
fizycznej precyzji audio. M6 i gotowość 1.0 pozostają otwarte. Publikacja beta.3
oraz smoke oficjalnie podpisanego APK nie należą do tego PR.
