# OpenMetronome 1.1.0

**Opis przygotowywanego wydania — niepotwierdzony jeszcze oficjalnym APK.**
PROD `org.openmetronome`, versionName **1.1.0**, versionCode **20**.
To planowane wydanie stabilne zwykłej aplikacji, bez nowego APK DEV.

## Zmiany względem 1.0.0

- Pełny ekran z dużym BPM, pulsem i taktem, blokadą dotyku z dostępnym Stop,
  utrzymywaniem ekranu i ograniczeniem migania, bez restartu sesji.
- Procenty 100/75/50/25% niezależne od bazy 20–300 BPM; wynik 5–300 BPM.
  Rampa zmienia bazę. Zmiana tempa od taktu albo następnego możliwego pulsu.
- Odliczanie 0/1/2 takty poza czasem praktyki, metra 5/4, 7/4, 5/8 i 7/8,
  grupowanie 5/8 i 7/8. W 6/8 BPM nadal oznacza ósemki.
- Statystyki 2.0: cały czas dzisiaj, podsumowanie, historia, analiza, filtry
  i progi 20 s/sesję oraz 5 min/aktywny dzień. Krótkie sesje pozostają w historii.
- Trzy nowe barwy: Naturalny, Suchy, Naturalny niski, z osobnymi akcentami.
  Dotychczasowe sześć brzmień zachowane. Krótsze podpisy UI, bez redesignu.

## Dane i aktualizacja

Room 3 z migracją z 1.0; import kopii `.ombak` v1/v2, domyślny eksport v2.
Eksport zgodny v1 ostrzega o pominięciach i odrzuca nowe metra lub barwy,
których 1.0 nie odczyta. Nieznany przebieg starych sesji nie jest zerem.
Nie zakładamy możliwości cofnięcia instalacji do niższego versionCode.
Nie odinstalowuj aplikacji ani nie czyść danych przy niezgodności podpisu.

## Walidacja i ograniczenia

Wyniki automatyczne i bramki:
[raport 1.1](https://github.com/Franek2009/OpenMetronome/blob/main/docs/V1.1-RELEASE-VALIDATION.md).
Regresja obejmuje JVM, PCM offline, Lint, oba warianty, ciche API26/35,
migracje, backup/restore i aktualizacje kopii podpisanych kluczem testowym.
Nie zastępuje weryfikacji oficjalnego APK.

Manualnie użytkownik potwierdził prawidłową aktualizację i import statystyk
oraz zaakceptował odsłuch prototypów trzech barw. Nie jest to pełny odbiór
finalnego APK 1.1 ani wszystkich scenariuszy M6. Fizyczne jitter i latencja
nie zostały zmierzone. Nie deklarujemy laboratoryjnej precyzji wyjścia.

Pełny rejestrator DEV pozostaje wyłączony po FAIL kwalifikacji narzutu API26;
wynik nie jest zaliczony ani blokujący wydanie PROD. Dodatkowe próbki VCSL
oczekują na wybór; brak osobnej barwy „Drewniany” nie blokuje 1.1.

## Przed publikacją

Po osobnej zgodzie na tag i podpisanie należy uzupełnić ten opis o rzeczywisty
wynik workflow, SHA-256, potwierdzenie dotychczasowego certyfikatu i czterech
oficjalnych aktualizacji 1.0.0 / beta.1 → 1.1.0 na API26/35. Wymagany także
odbiór finalnego APK przez użytkownika. Wtedy usunąć nieaktualny status
przygotowania, sprawdzić wszystkie publiczne linki i uzyskać zgodę na publikację.
Nie wpisywać nieistniejących sum ani niezaliczonych testów jako PASS.
