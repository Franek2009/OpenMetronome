# 1.1.0 — przygotowanie zwykłej aplikacji

## Zakres i zgody

PROD 1.1.0, versionCode 20 (po publicznej beta.1/code 19), pakiet
`org.openmetronome`, dotychczasowa konfiguracja podpisu. Ten etap nie zmienia
funkcjonalności aplikacji względem scalonych PR #25–27: tylko metadane wersji,
dokumentację i narzędzia wydania. Stable 1.0.0 i publiczna beta.1 pozostają nienaruszone.

Docelowo niepubliczny draft tylko PROD, `include_dev=false`, z trzema plikami:
APK, SHA256SUMS, SIGNING-CERT-SHA256.txt. Dla wersji bez sufiksu
`prerelease=false`, zawsze `draft=true`. Domyślne `include_dev=true` zachowuje
proces obu wariantów. DEV nie jest wymaganym artefaktem 1.1.

Tag, oficjalny klucz, workflow podpisywania i draft wymagają kolejnej zgody.
Publiczna publikacja wymaga jeszcze osobnej zgody po kontroli APK i odbiorze.

  Wymagane pełne 5/5: verify, ciche API26/35 oraz aktualizacje API26/35.
- verify: wszystkie JVM PROD/DEV, Lint debug/release, debug/instrumentacja/

  odmowa nadpisania; oficjalne bazy 1.0 i beta.1, rosnący code,
  odrzucanie błędnego certyfikatu/hashu/pakietu i debug przed instalacją.
  Używają atrap, bez sieci, kluczy i urządzeń.

## Osobne wyniki i ograniczenia

Manualne potwierdzenie użytkownika: aktualizacja i import statystyk bez zarzutu,
bez podanych szczegółów urządzenia/ścieżki. Zaakceptowano odsłuch prototypów
trzech nowych barw. Nie zaliczamy automatycznie odbioru finalnego APK 1.1.

FAIL pełnej rejestracji DEV API26: ostatnia próba aktywacji +14,05%,
próg +10% pozostaje. Rejestracja została wyłączona. Ten wynik nie jest
przemianowany na PASS; diagnoza i dalsza optymalizacja to osobne zadanie.

NOT RUN w tym etapie: oficjalne podpisanie 1.1, kontrola jego APK i cztery
aktualizacje oryginałów, fizyczne audio/wibracje, finalny odbiór użytkownika.
Jitter i latencja fizycznego wyjścia: **niezmierzone**. Brak nowych operacji
na telefonach, odinstalowania lub czyszczenia danych. Historyczny odbiór
RC2/1.0 nie jest automatycznym PASS całego M6 dla 1.1.

## GO/NO-GO

Do zgody na tag/podpisanie: dokładny końcowy main ma 5/5 PASS, metadane
1.1.0/code 20, brak kolizji tagu, brak dodatkowej funkcjonalności w PR wydania,
zachowane pakiety/Room/.ombak/podpis i sprawdzone gałęzie po scaleniu.

Do publikacji stable dodatkowo:

1. Osobna zgoda na tag wskazujący zatwierdzony SHA i oficjalny workflow PROD.
2. Wszystkie wymagane zadania workflow PASS; DEV pominięty jawnie.
3. Dokładny APK z draftu: zgodne SHA-256 i publiczny fingerprint
   `563cd960efc3fc5b483ceae4b96e66728af9e2bb0c52d6162fe37cded72ac4a2`,
   versionName 1.1.0/code 20, pakiet, manifest/uprawnienia, brak debug/test/DEV.
4. Na czterech świeżych emulatorach: oficjalne 1.0.0 → 1.1.0 i beta.1 → 1.1.0
   na API26 i API35. `verify-upgrade.sh --official` / `--official-beta`, znane
   SHA obu plików, bez przepodpisania; aktualizacja `install -r` bez kasowania.
   Porównanie ustawień, presetów, historii, statystyk i dokładnych bajtów sampla.
5. Użytkownik sprawdza finalny APK: aktualizacja/dane, nowa barwa i akcent,
   Start/Stop, tło/blokada ekranu, procenty/pełny ekran i statystyki. Problemy
   blokujące poprawić; brak pomiaru laboratoryjnego nie oznacza FAIL odsłuchu.
6. Zaktualizowany opis wydania z rzeczywistymi wynikami; zgodne trzy załączniki.
   Osobna zgoda na publiczne stable, później anonimowe pobranie i README.
