## Pełna regresja CI — wiązanie wyniku z commitem

Obowiązkowy workflow PR: `Android verification`. Sprawdzić **końcowy HEAD**,
nie wcześniejszy zielony commit. Opis PR wydawniczego podaje dokładny SHA,
link do przebiegu i końcowe wyniki pobranych raportów:

- verify: JVM, Lint debug/release, debug/test/release, skrypty i PCM offline;
- quiet API 26 i API 35: pełne ciche zestawy, w tym migracja Room 1→2,
  backup/restore, anulowania, błędy dysku, ponowienie końcowego zapisu i
  zabijanie procesu podczas restore/odzyskiwania;
- upgrade API 26 i API 35: beta.3→RC2, komplet ustawień, presetów, historii,
  dni i dokładnych bajtów sampli porównany na izolowanych danych.

Audio pozostaje jawnie pominięte (`allowAudio=false`, `allowHaptics=false`);
nie może być innych nieoczekiwanych pominięć ani niekompletnego raportu.
Upgrade w zwykłym CI używa kopii z jednorazowym kluczem testowym.
Nie jest to kontrola oficjalnego certyfikatu RC2 ani oficjalny→oficjalny upgrade.
Nie uruchamiano lokalnie kolejnej instrumentacji na fizycznych urządzeniach.

## Niewykonane i pozostałe bramki

- **NIEWYKONANE:** oficjalne podpisanie RC2, tag/draft, kontrola podpisanego
  APK i aktualizacje oficjalny RC1/beta.3→oficjalny RC2. Osobna zgoda dopiero

- **NIEWYKONANE:** praktyczny odbiór tej wersji RC2, automatyczne fizyczne
  audio i wibracje. Potwierdzenie użytkownika o zachowaniu danych przy
  beta.3→RC1 na A56 nie jest pełnym odbiorem RC2.
- **NIEZMIERZONE:** fizyczny jitter i latencja. Nie przypisujemy zer
  underrunów do ręcznych sesji. M6 i stabilne 1.0 pozostają otwarte.
- Pełny dysk odrzucający bazę i kolejkę może pozostawić najnowszy stan
  tylko w pamięci. Zabicie procesu może utracić fragment po ostatnim
  trwałym checkpointcie; test procesu nie jest testem odcięcia zasilania.

Po pełnym zielonym CI tego PR można rekomendować zatwierdzenie PR i osobny
proces podpisanego draftu RC2. Nie jest to zgoda na scalenie, tag, publikację
ani stabilne 1.0. Nie wykonywano operacji na telefonach i nie usuwano danych.
