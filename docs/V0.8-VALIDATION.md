# 0.8.0-beta.1 — przygotowanie publikacji

VersionCode 8. Bez zmian silnika audio i schematu danych. Krótszy pasek
nawigacji, dokumentacja publiczna oraz podpisywanie i GitHub Releases.

## Lokalnie — 2026-10-20

- 98 JVM PASS; Lint debug i release: 0 błędów, 0 ostrzeżeń.
- Debug, instrumentacja, niepodpisany i podpisany release: kompilacja PASS.
- Parser instrumentacji: 7 scenariuszy PASS; testy skryptów wydawniczych PASS.
- Actionlint 1.7.12: oba workflow bez błędów; lokalne linki Markdown poprawne.
- Negatywne kontrole: Gradle odrzucił oficjalny build bez zmiennych podpisu;
  pakowanie odrzuciło APK niepodpisany, debug i obcy certyfikat. Skrypt klucza
  odmówił nadpisania rzeczywistego magazynu. Test skryptu smoke odrzucił
  numer urządzenia fizycznego przed wykonaniem jakichkolwiek poleceń ADB.
- Podpis wydawniczy APK: v2, RSA 4096, właściwy certyfikat. Brak flagi debug,
  pakiet org.openmetronome, code 8 / 0.8.0-beta.1. Brak uprawnienia INTERNET.

Pierwsza analiza Lint została przerwana po utknięciu w przejściu drzewa PSI
(BidirectionalTextDetector). Powtórzenie na niezmienianym kodzie z dwoma
workerami zakończyło cały build w 2 min 25 s. Nie wyłączano tego detektora.
Ostrzeżenie ConfigurationScreenWidthHeight wyciszono tylko na celowym odczycie
wysokości do klasyfikacji okna: rozmiar treści z klawiaturą nie może zmieniać
wariantu tabletu. Nie służy to obliczaniu rozmiarów elementów w pikselach.

zaliczony na czystym runnerze: 98 JVM, parsery i kompilacja wszystkich trzech
APK. Pobrane XML potwierdzają zero błędów Lint, ale po 3 ostrzeżenia debug
i release: dostępne nowsze Gradle, AGP i coroutines. Lokalny tryb offline
nie zgłaszał tych sieciowych podpowiedzi. Nie aktualizowano zależności tylko
po to, aby usunąć informacyjne ostrzeżenia.

Tag v0.8.0-beta.1 wskazuje sprawdzony commit ad1acf4. Proces wydawniczy
[39449377494](https://github.com/Franek2009/OpenMetronome/actions/runs/39449377494)
zaliczył wszystkie cztery zadania: verify, sign, smoke, draft.

Użytkownik potwierdził kopię klucza poza komputerem („kopia gotowa”) i polecił
kontynuować. Po ponownej kontroli sumy APK, certyfikatu, tagu i zielonego CI
opublikowano istniejący draft 2026-10-20 o 15:58:21 UTC jako prerelease,
bez oznaczania go jako stabilne latest. Nie przebudowano ani nie zastąpiono APK.
[Publiczne wydanie](https://github.com/Franek2009/OpenMetronome/releases/tag/v0.8.0-beta.1).
Klucza i haseł nie ma w repozytorium; skonfigurowano tylko sekrety oraz publiczny
odcisk certyfikatu. Potwierdzenie kopii pochodzi od użytkownika; nie sprawdzano
zawartości jego nośnika. Nie wykonywano nowych prób audio ani instalacji.
Workflow zgłosił też adnotacje o Node 20 w upload/download-artifact v4;
runner uruchomił je na Node 24 i wszystkie zadania przeszły. Aktualizacja
tych akcji pozostaje zadaniem utrzymaniowym, nie ukrytym błędem builda.
Nie deklarujemy zakończenia M6 ani odbioru fizycznej precyzji wyjścia audio.

Chroniony główny katalog .git pozostał nietknięty. Do pierwszej publikacji
użyto osobnej kopii źródeł `.tooling/publish/OpenMetronome` z normalnym Git.
Nie jest to drugi zestaw danych aplikacji ani lokalizacja klucza. Po pobraniu
repozytorium z GitHuba zwykły klon działa standardowo; kopii publikacyjnej nie
należy traktować jako automatycznie synchronizowanego katalogu roboczego.
