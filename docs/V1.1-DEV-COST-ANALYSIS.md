## Nowe metryki — tylko test, po zatrzymaniu workera

- `devRenderBodyP99Ns`: p99 istniejącego pola c rekordów RENDER; obejmuje
  renderowanie i hooki wewnątrz niego, przed dopisaniem samego RENDER.
- `devPostRenderP99Ns`: p99 różnic **sparowanych bloków**: pełny pomiar minus
  czas c tego samego bloku. Obejmuje dopisanie RENDER i końcowy zegar CPU.
  Nie odejmujemy od siebie niezależnych percentyli i nie sumujemy p99.
- `baselineSpreadRatio`: większe / mniejsze bazowe p99, wyłącznie informacja.

Analiza odczytuje już istniejący dziennik po Stop. Sprawdza indeks/ramkę
bloku i długość okna. Nie dodaje pomiarów do wątku audio. Pozostają dokładnie
3000 bloków rozgrzewki i 3000 pomiaru, ta sama kolejność i niższa baza,
ten sam pełny budżet +10% oraz kryteria PCM/strat. Pola są dodatkiem do
raportu testowego, nie zmianą formatu ZIP diagnostyki aplikacji.

Wniosek: koszt końcowego dopisania nie wyjaśnia samodzielnie całej
zmienności między próbami. To **nie dowód**, że narzut producenta jest
zerowy albo że FAIL CI jest fałszywy. Brakuje podstaw do kolejnej
spekulatywnej zmiany synchronizacji lub do aktywacji flagi.
Następny krok techniczny: zbadać stabilność faz ART/JIT oraz bazowego
workera, korzystając z tego rozbicia, zanim zmienimy producenta lub protokół.
