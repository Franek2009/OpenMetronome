# OpenMetronome 1.2.1 — plan weryfikacji

Status: wersja w przygotowaniu; oficjalny APK 1.2.1 nie jest jeszcze podpisany ani wydany.
Istniejące 1.2.0 pozostaje wydaniem stabilnym. Nie utożsamiać testów na emulatorze
z odbiorem widgetów na fizycznym launcherze ani z pomiarem fizycznego audio.

## Plan: oficjalna aktualizacja 1.2.0 → 1.2.1

1. Po osobnej zgodzie przygotować podpisany dotychczasowym certyfikatem APK 1.2.1,
   `org.openmetronome`, versionCode 22, versionName `1.2.1`. Sprawdzić jego manifest,
   podpis i SHA-256 oraz zgodność z zatwierdzonym tagiem i artefaktem wydania.
2. Pobrać oryginalny opublikowany APK 1.2.0/code 21 i porównać SHA-256
   `0679575ed389feeb1edf6ee32f446fbd955ef3b86a187372d0eb1950c3e574fc`
   i certyfikat SHA-256
   `563cd960efc3fc5b483ceae4b96e66728af9e2bb0c52d6162fe37cded72ac4a2`.
3. Przed próbą jawnie rozszerzyć narzędzie `scripts/verify-upgrade.sh` o bezpieczny,
   testowany wybór oficjalnego punktu wyjścia 1.2.0/code 21. Obecny tryb
   `--official` oczekuje 1.0.0/code 18 i nie realizuje tej ścieżki. Nie zmieniać
   ani nie usuwać istniejącej regresji CI z 0.13.0-beta.3.
4. Na osobnych, świeżych emulatorach API 26 i 35 zainstalować oficjalne 1.2.0,
   utworzyć izolowane dane testowe, następnie zainstalować oryginalny podpisany
   APK 1.2.1 przez `install -r`. Żadnego przepodpisywania, odinstalowywania ani
   czyszczenia danych podczas aktualizacji.
5. Porównać ustawienia, presety, historię, statystyki, kopię i dokładne bajty
   własnego sampla. Zapisać wyniki każdego API, sumy, podpisy i ograniczenia.
   Testy ciche nie uruchamiają audio ani wibracji.

Żadnego z powyższych kroków podpisywania i oficjalnej aktualizacji jeszcze nie
wykonano. Pozytywne CI bieżącego PR nie stanowi dowodu tych dwóch ścieżek.
